# Connect after an unrecognised weigh-in to check the user list

After a factory reset or after a scale user is deleted on the scale, the scale never lists that slot as pending again. A sync-on-pending design would then simply go quiet. So when a wake reaches about 25 s and no managed slot is pending, HA still connects, reads the user list (which needs no consent) and disconnects. A missing slot or an empty list raises a repair issue. A failed consent triggers the same check. This costs one extra connection of about 10 s per unrecognised weigh-in, and lets HA tell the user that someone was not recognised and needs teaching. That notification is a per-scale option and on by default. The 25 s wait matters: connecting during a weigh-in and consenting someone else aborts it, with no reading stored (verified through a proxy, #24).

The same moment serves slots that were pending before the wake. The scale appends the weigh-in's slot to its slot list once the weigh-in is final, 4–10 s after stepping on. So only a slot appended to a later scan response of the wake means "final now, connect". Which slots were pending before is read from the wake's first scan response, never from what HA remembers of earlier wakes (lost on a restart) or from a time window (the first scan response came 11 s late once). A slot list merged into a plain advertisement can be from an earlier wake, so only scan responses count.

A wake in which no scan response arrived at all (a passive path) says nothing about who stepped on, so it neither notifies nor assumes pending slots; HA asks for an active scan at each wake's start, and three such wakes in a row raise a repair issue that clears with the next scan response (#22). The user-list check and the deletions still run at 25 s.

None of this applies to the scale's advertising right after HA's own disconnect: it goes on for 0-20 s, which would otherwise look like a wake that reaches 25 s and trigger a redundant connection and a false "unrecognised" notification (#25). The end of any HA session (a sync, a check, a flow's teaching session) is remembered, and advertisements that start within 5 s of it are not a wake for this purpose. A slot appended to a later scan response of such advertising still syncs.
