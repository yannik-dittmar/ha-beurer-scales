# Garmin Connect is an opt-in link per scale user, a separate subentry that stores only tokens

A scale user can send each fresh reading to Garmin Connect. This is a cloud push, not a Bluetooth feature, so it sits beside the scale user instead of inside its flow: a second subentry type, `garmin_connect`, whose data only names its scale user (`scale_user` = the subentry id). One link per scale user, enforced by the subentry `unique_id`. The scale user's own subentry, its create/adopt/reconfigure flows and its wake-window machinery stay untouched, and removing the link or the scale user removes the other (the update listener drops a link whose scale user is gone, which also covers a factory reset).

We use `garminconnect` (pinned in `manifest.json`), the only maintained library whose login still works; `garth` is deprecated. Its login is blocking and slow on purpose, so setup runs it in the executor behind a progress step, with a second step for the MFA code. The password is used once and never stored. What persists are the three token strings the login returns, in a private `Store` (file mode 0600), not in the subentry: the entry's data file is world-readable, and updating a subentry reloads the scale and would cut off a sync. Garmin's login is what gets throttled and what sends MFA mails, so nothing ever logs in again by itself. If Garmin rejects the tokens, pushing pauses, readings keep queueing, and a repair issue asks the user to reconfigure the link, which logs in again. Throttling (429) and outages are retried with a growing delay and keep the tokens.

Each fresh reading is queued in the same store before it is sent, so an outage or a restart loses none, and the newest sent timestamp prevents sending a reading twice after a crash between upload and save. Backlog and guessed readings never get this far (ADR 0005, ADR 0006). Garmin stores fewer values than the scale measures; the visceral fat index goes to Garmin's rating field, not its kg field.

The library comes with `curl_cffi`, a native dependency, and is a hard requirement of the whole integration: Home Assistant has no optional requirements. If a future HA release stops the install, the integration doesn't load until the pin moves. We accept that for one dependency over a second integration. Garmin changes its login every few months; the Garmin code is kept in `garmin.py` so the library can be swapped.
